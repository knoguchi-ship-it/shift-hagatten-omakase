# 実装グランドルール

1. **DRY** — 制約判定・日付計算・表示名・色は一箇所で定義し、UI、生成、検証、Excel出力で共有する。
2. **単一責務** — SQLiteリポジトリ、制約検証、生成エンジン、IPC、画面コンポーネントを分離する。
3. **型安全** — `unknown` のまま境界を越えない。IPCペイロードを検証し、ドメイン型を共有する。
4. **安全な変更** — 既存データを物理削除しない。破壊的操作は影響と確認を必須にする。
5. **テスト可能性** — 生成・制約検証はUIやElectronに依存しない純粋なモジュールとして実装する。
6. **性能** — 大量セルを全描画せず、重い生成はUIスレッドで実行しない。
7. **アクセシビリティ** — ネイティブ要素を優先し、カスタムグリッドはARIA Gridのフォーカス・キーボード規約に従う。
8. **日本語業務UX** — 曖昧なアイコンだけの操作を避け、状態・影響・エラー理由を日本語で明示する。
9. **完了制御** — 計画に未完了項目がある間は、完了報告として作業を終えない。型チェック、部分実装、ビルド成功は進捗であり完了条件ではない。最終報告は、受入基準、E2E回帰テスト、第三者評価、セキュリティ確認、配布物検証をすべて通過した場合に限る。
10. **継続実行** — ユーザーから「継続」「完成まで」と指示されたタスクは、ブロッカーがない限り次の実装・検証単位へ進む。中断が必要な場合は、技術的事実と必要な判断だけを明示する。
