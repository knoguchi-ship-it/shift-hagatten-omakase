# 自己監査 — 2026-08-28

## 結論

**現行版を「グローバルスタンダードに適合」または「業務利用可能」とは判定しない。**

Electronの隔離、IPC送信元検証、復元前バックアップ、仮想グリッド、論理削除などの土台はある。一方で、データ喪失を防ぐ操作設計、SQLiteの参照整合性、`file://`運用時のCSP、支援技術でのグリッド操作、入力エラーの提示が未達である。WCAG 2.2 AAをアクセシビリティの目標、Electron公式のSecurity Checklistをデスクトップ・セキュリティの基準として、実機と自動評価で再確認する必要がある。

## 是正実施記録（2026-08-28）

P0の3項目とP1の実装項目を完了した。なお、下記は静的/単体テストでの確認であり、実機E2Eと受入評価は未完了である。

- `file://`を廃止し、配布済みRendererディレクトリだけを配信する`shiftc://app`カスタムプロトコルへ移行した。URLデコード後のディレクトリトラバーサルを拒否し、CSP回避権限は付与していない。権限要求・権限確認は既定拒否にした。
- 未保存状態をアプリ全体でMainへ通知し、画面移動時は破棄確認、生成・Excel出力時は保存要求、アプリ終了時はキャンセルを既定にした。既存月を開く導線も追加した。
- 削除済み勤務種別は、新規割当候補から除外しつつ、その勤務種別を参照する過去月では表示・Excel出力に必要な定義を返すようにした。削除時は勤務セル・必要人数・翌日ルールへの影響を表示する。
- 条件保存と設定保存をそれぞれ単一IPC・単一SQLiteトランザクションに統合した。日付形式、ID、人数の整数/非負、参照先、希望休と勤務の排他を境界で検証し、失敗時はロールバックする。
- 生成中止は`postMessage`待ちではなく`SharedArrayBuffer`/`Atomics`を用いた協調中止に変更した。
- 利用者向けの保存/出力/生成/起動エラー表示、toastのlive region、名前付きGrid、キーボード操作できる違反遷移を追加した。
- SQLiteスキーマをバージョン2へ移行した。新規DBには外部キーと業務値の`CHECK`を定義し、旧DBはトランザクション内で新表へ複写して`foreign_key_check`を通過した場合だけ置換する。不整合や値制約違反時はロールバックし、元のDBを変更しない。旧月の勤務履歴を残す移行テストも追加した。
- 勤務種別の開始・終了時刻、勤務日カウント、職員の雇用区分、職種の表示順、NGペア/翌日ルールの削除を実装した。時刻は共有型・DB・IPC検証・マスタUI・Excel列見出しまで伝播する。保存画面で新規マスタと新規ルールを同時登録するときは、仮IDをDB採番IDへ解決して参照を保つ。
- 職員削除にも履歴、NGペア、勤務不可条件の影響表示と明示確認を追加した。グリッドは行・列の説明とキーボード操作説明を支援技術へ公開した。

残る優先課題は、Gridの完全なARIA行構造とフォームエラーの関連付け、スクリーンリーダー/50名×31日/Windows実機での受入評価である。

- 自動生成はRendererからWorkerへ分離され、180秒上限と違反一覧を持つ。
- SQLiteバックアップAPI、復元前バックアップ、サイズ・整合性・主要テーブル検証、論理削除、Excel出力、50名×31日用フィクスチャは存在する。
- グリッドには仮想化と矢印キー移動、編集、コピー/貼り付け、セルへの違反遷移の基礎実装がある。

## 実装済みだが再検証が必要な領域

- IPC: 送信元検証は全ハンドラにある。さらにElectron公式に沿って、権限要求を既定拒否するハンドラ、カスタムプロトコル、Electron Fusesを設定し、依存関係を固定・定期更新する。
- 色と表示: 予定セルは略称も表示するため完全な色依存ではないが、違反/未保存/削除済みの識別、各勤務色、最小文字コントラストはテーマを含めて測定する。
- 性能: 編集グリッドは仮想化されるが、条件画面の希望休表は全セルを描画し、セル探索も線形である。50名×31日・拡大表示・低性能PCで計測して閾値を定義する。
- テスト: 現行E2Eは2件のみで、未保存保護、キャンセル、既存月を開く、削除後履歴、失敗時ロールバック、入力境界、アクセシビリティ、復元を回帰対象にしていない。

## 準拠目標と参照

- アクセシビリティ目標: WCAG 2.2 AA。WCAGはキーボード操作、可視フォーカス、ラベル/エラー、ステータスメッセージ、色以外の識別を要求する。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- カスタムグリッド: WAI-ARIA Authoring PracticesのGridパターン。Tabでグリッドへ入り、矢印キーでセル移動でき、セル内編集とフォーカス復帰を一貫して扱う。[WAI-ARIA Grid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)
- Electron: context isolation、sandbox、CSP、IPC送信元検証、権限要求の制御、`file://`回避を確認対象にする。[Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)
- データ整合性: SQLiteの外部キーは明示定義と有効化により参照関係を強制できる。[SQLite Foreign Key Support](https://www.sqlite.org/foreignkeys.html)
